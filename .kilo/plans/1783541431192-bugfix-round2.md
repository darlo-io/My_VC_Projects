# quran_app — Bugfix round 2 (2026-07-17)

User-reported bugs from device testing on `c1316607` (OPPO CPH2653).

## ✅ Bug 1: Screen doesn't rotate

**Root cause**: `lib/main.dart:19-22` вызывал
`SystemChrome.setPreferredOrientations` с **только** portrait
вариантами:

```dart
await SystemChrome.setPreferredOrientations([
  DeviceOrientation.portraitUp,
  DeviceOrientation.portraitDown,
]);
```

`AndroidManifest.xml` НЕ имеет `android:screenOrientation` атрибута
(наследует `unspecified` от application), и `MainActivity.kt` —
просто `class MainActivity : AudioServiceActivity()` без
orientation lock. Так что проблема была **исключительно в main.dart**.

**Fix**: добавлены `landscapeLeft` и `landscapeRight`:

```dart
await SystemChrome.setPreferredOrientations([
  DeviceOrientation.portraitUp,
  DeviceOrientation.portraitDown,
  DeviceOrientation.landscapeLeft,
  DeviceOrientation.landscapeRight,
]);
```

`AndroidManifest.configChanges` уже включает `orientation|screenSize`,
так что Activity не пересоздаётся при rotation — Flutter
обрабатывает событие через `MediaQuery`, и `_LandscapeSidebar`
появляется в landscape.

**User verification needed**: повернуть устройство физически (ColorOS
блокирует programmatic rotation).

## ✅ Bug 2: Tafsir doesn't load — **3 отдельные root causes!**

### 2.1. Response key — singular vs plural

**Root cause**: Quran.com v4 API для `/tafsirs/{id}/by_ayah/{key}`
возвращает:

```json
{"tafsir": {...}}  ← singular
```

НЕ `{"tafsirs": [...]}` как `/by_chapter` или `/resources/tafsirs`.

Код читал `r.data?['tafsirs']` → null → возвращал `null` →
UI показывал CircularProgressIndicator бесконечно.

Подтверждено curl:
```bash
$ curl https://api.quran.com/api/v4/tafsirs/14/by_ayah/1:1
{"tafsir":{"verses":{"1:1":{"id":1}},"resource_id":14,...,"text":"..."}}
```

**Fix**: `lib/features/audio/data/quran_com_api.dart:198` и
`lib/features/tafsir/data/quran_com_tafsir_api.dart:59` —
`['tafsirs']` → `['tafsir']` + проверка `obj == null`.

### 2.2. Wrong id passed to API — local vs Quran.com

**Root cause**: `tafsir_panel.dart:352`:
```dart
quranComTafsirId: source.id,  // ← local DB id!
```

`s.id` — это `TafsirSources.id` (auto-increment PK в локальной БД),
НЕ Quran.com id. API возвращал 404 → `TafsirNotFoundException`
catch'ился silently, UI показывал loading.

**Fix**: использовать `source.quranComId ?? source.id`:
```dart
final quranComId = source.quranComId ?? source.id;
quranComTafsirId: quranComId,
```

### 2.3. ReceiveTimeout слишком короткий

**Root cause**: на медленных сетях (curl test на c1316607 показал
**24KB / 10 секунд**) 12s receiveTimeout Dio отваливался ДО
конца ответа. Tafsir text — 30-50KB, реальная загрузка 15-25s.

**Fix**: `quran_com_tafsir_api.dart:18-22`:
- connectTimeout: 8s → **20s** (DNS на плохих сетях)
- receiveTimeout: 12s → **60s**

## ⚠️ Bug 3: Tafsir names in English — **ограничено upstream**

**Что попробовал**:

Sprint 2.5.1: добавил `nameRu` колонку в `tafsir_sources` (migration
v15→v16), обновил `TafsirsSyncService.forceSync` чтобы писать
русский перевод в `nameRu` (а не в `nameEn`), добавил
`_localizedSourceName(s, lang)` helper в `tafsir_panel.dart` который:
- `ru` → `nameRu` ?? `nameAr` ?? `nameEn`
- `en` → `nameEn`
- `ar` → `nameAr` ?? `nameEn`

**Реальность (curl `/api/v4/resources/tafsirs?language=ru`)**:
```json
[{"id":14,"name":"Tafsir Ibn Kathir","author_name":"Hafiz Ibn Kathir",
  "language_name":"arabic","translated_name":{"name":"Tafsir Ibn Kathir",
  "language_name":"english"}},
 {"id":91,"name":"السعدي Al-Sa'di","author_name":"Saddi",
  "language_name":"arabic","translated_name":{"name":"السعدي Al-Sa'di",
  "language_name":"english"}},
 {"id":170,"name":"Al-Sa'di","author_name":"Saddi",
  "language_name":"russian","translated_name":{"name":"Al-Sa'di",
  "language_name":"english"}}, ...]
```

**Quran.com НЕ возвращает русский перевод** для Arabic-original
таfsirs даже с `?language=ru`. Параметр `language` влияет только
на `translated_name.language_name`, но `translated_name.name`
остаётся английским для non-Russian tafsirs.

Из ~20 tafsirs только 1 (`id=170, slug=ru-tafseer-al-saddi`) — реально
Russian-original, с `language_name="russian"`. Остальные Arabic/English/
Bengali/Urdu — все `translated_name.name` = English.

**Правильный partial-fix**: для ru-локали fallback показывает
**author_name** (которое мы НЕ сохраняем в БД) — это дало бы
"Hafiz Ibn Kathir" вместо "Tafsir Ibn Kathir". Не реализовано
в этом коммите (требует ещё одной колонки + миграции).

**User-visible result**:
- Source list остаётся на английском (потому что API даёт English)
- Аят 1:1 tafsir (Ibn Kathir на арабском) теперь должен
  загружаться (Bug 2 fixed) → показывать арабский текст через
  `_stripHtml`. Текст арабский — нечитаем для русского, но это
  honest representation of what's available.
