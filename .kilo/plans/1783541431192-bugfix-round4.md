## Bug 3 — Tafsir loading (Round 4 попытка)

### Round 3 implementation (failed)
`fetchTafsirForAyah` правильно разделяет local id vs quranComId, API вызов правильный. Curl test подтвердил API работает за 0.5s на устройстве. Но UI бесконечно показывает spinner — `fetchTafsirForAyah` висит без exception.

### Round 4 — Multiple timeout layers

1. **`lib/features/tafsir/data/tafsirs_sync_service.dart`**:
   - Добавлен `.timeout(90s)` на API-вызов `_api.fetchByAyah(...)` 
   - При timeout возвращает null → fetchTafsirForAyah кидает `TafsirNotFoundException` → UI показывает empty-state с retry

2. **`lib/features/quran/presentation/widgets/tafsir_panel.dart`**:
   - `_fetch` оборачивает вызов `fetchTafsirForAyah().timeout(60s, onTimeout: ...)`
   - При TimeoutException показывает явный error: "Превышено время ожидания (60s). Проверьте сеть..."
   - Различает `TimeoutException` vs `TafsirNotFoundException` для разных сообщений
   - Добавлен `Timer? _slowLoadTimer` (запасной вариант, не сработал на устройстве)
   - `stderr.writeln` debug логирование для отладки

### Critical debugging finding (2026-07-22)

Через `adb logcat -s flutter` на устройстве были пойманы логи:
```
I/flutter: [tafsir_panel] build() called, lang=ru, _fetchedFor=false, _selectedSource=170
```
(`stderr.writeln` подтвердил что build запускается), НО:
- Нет логов от `_buildTafsirContent` builder (`[tafsir_panel] _buildTafsirContent builder fired`)
- Нет логов от `_fetch START` / `_fetch FAILED` / `_fetch SUCCESS`

**Вывод**: StreamBuilder.builder **не вызывается** после tap на source, несмотря на то что `_TafsirPanelState.build()` работает и `_selectedSource=170` установлен. Спиннер, который видит пользователь — это `StreamBuilder` в состоянии `connectionState.waiting`, builder которого ни разу не сработал.

### Возможные причины (гипотезы, не подтверждены):
1. `watchByAyahAndSource` не эмитит — StreamBuilder в состоянии waiting, builder не вызывается пока нет данных
2. `_fetchedFor` действительно `true` в момент проверки (но log показывает `false`)
3. `_buildTafsirView` или `_buildTafsirContent` не вызывается из-за какой-то условия в `build()`

### Workaround на устройстве

Пользователь получает tafsir panel без ожидания — если fix не помогает, придётся проверить через:
- `adb logcat -s flutter` после tap → смотреть какие callbacks срабатывают
- Возможно, проблема в кеше drift который не эмитит новые записи
- Возможно, нужна явная инвалидация через `ref.invalidate(_ayahTafsirStreamProvider(...))`

## Что делать дальше

Если tafsir loading остаётся проблемой:
1. **Проверить что StreamBuilder.builder вызывается** через `stderr.writeln` прямо в builder (не в `if (!_fetchedFor)` блоке, а в самом начале)
2. **Если builder НЕ вызывается** — это значит `cached` stream не имеет initial emit, и StreamBuilder ждёт навсегда. Решение: добавить `initialData: const []` к StreamBuilder чтобы builder вызвался с пустым data сразу
3. **Если builder вызывается, но _fetch не запускается** — проверить что `_fetchedFor` действительно `false` на момент проверки (может быть race condition)

Альтернативный fix: добавить `initialData: const <Tafsir>[]` к StreamBuilder чтобы spinner показывался сразу и builder запускался с пустым data.
