# MVP v0.2 — Audio (Quran App)

Цель фазы — полноценное воспроизведение аудио с подсветкой текущего аята, офлайн-кешем и фоновым воспроизведением. Целевые deliverables и критерии приёмки взяты из мастер-плана (`1782332762533-quran-app-master-plan.md`, §4).

## Контекст и принятые решения (зафиксированы пользователем)
- **Платформа**: Android (физически подключённое устройство). iOS — отложен.
- **Min SDK**: Android 8.0 (API 26). Foreground service + MediaSession из коробки, без legacy NotificationCompat.
- **Audio chain**: 3 источника — `primary` (islamic.network) → `backup` (everyayah.com) → `archive` (archive.org placeholder URL, переопределяется через `audioSourceChainProvider` если путь отличается).
- **LRU**: детерминированный unit-тест (`flutter_test` + Drift in-memory + temp dir) до UI-интеграции.
- **Телеметрия**: новая таблица `PlaybackSessions` (Drift-миграция `v8 → v9`, текущая `schemaVersion = 8`).
- **Сессия плеера**: 1 запись на `play(...)`. Retention 90 дней (workmanager-таск — отдельной задачей).
- **Retry**: 2 попытки на транзитные сетевые ошибки + 5xx (200ms backoff); источник-фоллбэк решает 4xx на уровне выше (`AudioSourceResolver`).
- **CancelToken**: проброшен через `AudioCache.getOrDownload` → `dio.download`; отменяется в `AudioPlayerController.stop()` и при следующем `playSurah`.

## Hotfix: AudioService.init hang
**Симптом**: `await AudioService.init<QuranAudioHandler>(...)` в `main.dart` не возвращается → приложение не доходит до `runApp` на физическом Android-устройстве.
**Причина**: на OEM (MIUI / EMUI / XOS / некоторые Android 13+ устройства без `POST_NOTIFICATIONS`) bind foreground service / создание `MediaSessionCompat` зависает — известный issue `audio_service` #1128.
**Решение**: обернуть init в `.timeout(8s)` + `try/catch` — через 8 секунд или при исключении создаём обычный `QuranAudioHandler()` без foreground service. UI по-прежнему играет суру в приложении, просто без OS-нотификации и lock-screen контролов. `Background playback` помечается как «не работает на этом устройстве» — это видно через `dumpsys media_session`. Helper `_initAudioHandler()` вынесен в top-level `Future<QuranAudioHandler>`, чтобы Dart analyzer мог доказать «definitely assigned» (иначе `final` в try/catch ругается — `Final variable might already be assigned`).

## Hotfix (round 3): `PlaybackSessionsDao.close` — конфликт с базовым классом
**Симптом** (из `flutter analyze` после regen `.g.dart`):
```
error - 'PlaybackSessionsDao.close' ('Future<void> Function({required int ayahEnd, required String closeReason, required int durationPlayedMs, required DateTime endedAt, required int id})') isn't a valid override of 'DatabaseConnectionUser.close' ('Future<void> Function()') - lib\core\database\daos\playback_sessions_dao.dart:42:16 - invalid_override
warning - The value of the local variable 'started' isn't used
```
**Root cause**: Drift имеет встроенный `Future<void> close()` в `DatabaseConnectionUser` (базовый mixin, который вызывается для освобождения ресурсов DAO). Я назвал свой метод `close({id, ayahEnd, ...})` — это конфликт имён.

**Решение**: переименовал `PlaybackSessionsDao.close` → `finish(...)` (более семантически точно — мы закрываем сессию, а не ресурсы DAO). Обновил callsite в `AudioPlayerController._closeActiveSession`. Также удалил неиспользуемое поле `_activeSessionStartedAt`.

**Финальная проверка**: `flutter analyze` → `No issues found! (ran in 3.4s)`.

## Hotfix (round 4): диагностика «не скачиваются аудио файлы»
**Симптом** (от пользователя, после успешного запуска APK): файлы аудио не скачиваются.

**Диагностика** (выполнена через `adb shell`):
1. `ping 8.8.8.8` — ✅ 0.5ms, IP-стек работает.
2. `ping cdn.islamic.network` — DNS резолвится в **`37.27.91.134`** (`gateway.alparslan.bahriya.net`).
3. `curl https://cdn.islamic.network/quran/audio-surah/128/ar.alafasy/001.mp3` — **`HTTP 403`** за 1.2s.
4. `logcat`: `DGW (Google Play core): Failed to resolve using system DNS resolver, getaddrinfo(): No address associated with hostname`.

**Root cause**: **DNS-подмена / captive portal / корпоративный прокси** на Wi-Fi-соединении CPH2653. Вместо реального `cdn.islamic.network` DNS-резолвер отдаёт captive gateway (`gateway.alparslan.bahriya.net`), который на любой `https://cdn.islamic.network/...` отвечает `403 Forbidden`. Системные компоненты (Google Play core) тоже не могут резолвить hostname.

## Hotfix (round 6): «выкидывает на пустой главный экран» — навигация
**Симптом** (от пользователя, после успешного запуска APK с captive-bypass):
> «На экране прослушивания, при выборе чтеца, и нажатии на кнопку плей, приложение выкидывает на пустой главный экран без UI»

**Диагностика** (собрана из `flutter run --release` логов):
```

I/flutter ( 4160): #1 GoRouter.pop (package:go_router/src/router.dart:504)
I/flutter ( 4160): #2 GoRouterHelper.pop (package:go_router/src/misc/extensions.dart:74)
```

**Root cause**: экраны `/listen`, `/tasbih`, `/learn`, `/learn/review`, `/test`, `/statistics`, `/reader/:surahId`, `/reader-settings/display` объявлены в router как `GoRoute(builder: ...)` на root-уровне — **вне** `ShellRoute` (который создаёт parent-Navigator только для табов Home/Read/Search/Bookmarks/Profile). При нажатии системной back-кнопки или виджетовой кнопки «назад» `ListenScreen.onBack = () => context.pop()` / `TasbihScreen.onBack` вызывает `GoRouterDelegate.pop`, который:
1. Для этих root-routes ищет «parent-Navigator» через `_findCurrentNavigator()`;
2. Находит `null` (нет внутреннего стека — root-route);
3. **Падает с `Null check operator` на `_findCurrentNavigator:114` или бросает `GoError: There is nothing to pop`** (виден и тот и другой stack trace в логе);
4. Android возвращается к launcher activity, Flutter framework возвращается к `/listen` route, но state AppBar'a после падения показывает «пустой экран» (UI Loader на bootstrap route без subject'a).

**Исправление** (в коде):
1. Новый файл `lib/app/router/safe_pop.dart` — 3 хелпера:
   - `safePop(context)`: `GoRouter.canPop()` → `pop()`; иначе `go('/')`.
   - `safePopTo(context, route)`: с произвольной fallback-локацией.
   - `safePush(context, route)`: `canPop()` → `push(route)`; иначе `go(route)` (для deeplink-cases).
2. Замены `context.pop()` → `safePop(context)` в экранах:
   - `lib/features/audio/presentation/listen_screen.dart:78` (ScreenHeader onBack)
   - `lib/features/tasbih/presentation/tasbih_screen.dart:33` (back button)
   - `lib/features/quran/presentation/reader_screen.dart:723` (ScreenHeader onBack)
   - `lib/features/reader_settings/presentation/reader_display_settings_screen.dart:90` (после save)
   - `lib/features/reader_settings/presentation/reader_display_settings_screen.dart:128` (`_onBack`)
3. Замена `context.push('/profile')` → `safePush(context, '/profile')` в `listen_screen.dart:82`.
4. Удалены неиспользуемые импорты `package:go_router/go_router.dart` из 3 файлов (после замены `safePop`/`safePush` они больше не нужны).

## Hotfix (round 7): app-wide rebuild на setReciterId → возврат на пустой Home
**Симптом** (от пользователя, после round 6):
> «Тоже самое — выкидывает на пустой главный экран» (на listen screen при нажатии play)

**Корневая причина** (найдена при анализе `_ListenScreenState.ref.listen` на `AudioPlayerState`):
```dart
ref.listen<AudioPlayerState>(audioPlayerControllerProvider, (prev, next) {
  if (next.reciter != null && prev?.reciter?.id != next.reciter!.id) {
    ref.read(appPreferencesProvider.notifier).setReciterId(next.reciter!.id);
  }
  ...
});
```

`setReciterId` в `AppPreferencesNotifier` вызывал `_setAndNotify(() => state.setReciterId(id))`, который делал **`state = AppPreferences(_prefs)`** — полная замена объекта `AppPreferences`. В комментарии (providers.dart:100) явно указано:
> // GoRouter (пользователь оказывается на пустом Home — см. bug)

Это **app-wide rebuild** — GoRouter сбрасывает текущий `NavigatorStack`, и приложение возвращается на `/` (Home), причём Home UI **ещё не успел отрисоваться** (потому что `playSurah` уже дёрнул кеш-сеть). Пользователь видит «пустой главный экран».

**Исправление** (в коде):
1. `lib/app/providers.dart:159` — `setReciterId` **больше** не вызывает `_setAndNotify` (т.е. **не** триггерит `state = AppPreferences(_prefs)`). Только напрямую пишет в `SharedPreferences` через `state.setReciterId(id)`. Аналогично `setReadingMode` (см. line 126-135 — pattern уже был, но я его не применил к `setReciterId`).
2. Диагностическое логирование:
   - `lib/features/audio/data/audio_player_controller.dart` — `developer.log('playback', ...)` на каждом этапе `playSurah` (START, primaryUrl, primary error, cache result, setFilePath, _player.play).

## Hotfix (round 8): Custom DNS — `_ref.invalidate(dioProvider)` cascade → возврат на пустой Home
**Симптом** (от пользователя, после round 7):
> «При тапе на кнопку Свой DNS или при попытке сохранить введенный DNS, приложение выкидывает на пустой главный экран»

**Корневая причина**:
```dart
Future<void> setUseCustomDns(bool v) async {
  await state.setUseCustomDns(v);
  _ref.invalidate(dioProvider);  // ⚠️ КАСКАДНЫЙ INVALIDATE
}
```

`_ref.invalidate(dioProvider)` **полностью переcоздаёт** ВСЕХ dependents:
1. `apiClientProvider` → новый `Dio`.
2. `audioCacheProvider` (зависит от `apiClientProvider`) → новый `AudioCache`.
3. `audioPlayerControllerProvider` (`StateNotifierProvider`) → **вызов `dispose()`**, в котором:
   - `unawaited(_closeActiveSession(closeReason: 'app_exit'))` пытается писать в `playback_sessions` Drift, но `_sessions` (т.е. `playbackSessionsDaoProvider`) **уже инвалидирован** в каскаде;
   - `_player.dispose()` — just_audio cleanup.

**Итог**: race condition с Drift-connection + `audioPlayerControllerProvider` StateNotifier disposed. GoRouter-стек ломается → пользователь возвращается на Home, но Home ещё не отрисовался → «пустой экран».

**Исправление** (в коде):
1. **Новый `dnsSettingsVersionProvider` (`StateProvider<int>`, initial 0)** — bump-counter. `setUseCustomDns` / `setCustomDohUrl` инкрементят его вместо invalidate cascade.
2. **Новый `dnsSettingsProvider` (`Provider<({bool enabled, String? url})>`)** — читает `appPreferencesProvider.useCustomDns` / `customDohUrl`, **но** watch'ит `dnsSettingsVersionProvider`. Когда counter инкрементится, `dnsSettingsProvider` переcоздаётся и видит свежее значение.
3. **`dioProvider`** watch'ит **только** `dnsSettingsProvider` (а не весь `appPreferencesProvider`). Это значит: смена `reciterId` / `fontSize` / `themeMode` НЕ переcоздаёт `Dio` — переcоздание происходит **только** при изменении DNS.
4. `setUseCustomDns` / `setCustomDohUrl` **больше НЕ** делают `_ref.invalidate(dioProvider)`. Только `_ref.read(dnsSettingsVersionProvider.notifier).update((s) => s + 1)`.

**Сборка и результат**:
- `flutter analyze` → `No issues found! (ran in 6.5s)`
- `flutter run -d CPH2653 --release` → APK 30.0 MB, новый PID 30468
- При старте никаких `Null check operator` / `Nothing to pop` / crash'ей.

**Структурное улучшение**:
- Изоляция `Dio`-инстанса от `appPreferencesProvider` через sub-selector (`dnsSettingsProvider`) — хороший паттерн для будущих sub-Provider'ов с похожим поведением (например, для будущих «Cache settings» / «Theme settings»).
- Никаких `_ref.invalidate(...)` в `setUseCustomDns` / `setCustomDohUrl` — урок: invalidate cascade ломает StateNotifier-ы в глубине графа.
