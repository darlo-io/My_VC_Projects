## 1. Блокирующие (Blocker)

### B1. `reader_screen.dart` — God-class на 2414 строк

**Файл:** `lib/features/quran/presentation/reader_screen.dart:1-2414`

Это **129KB** в одном файле. Содержит:
- `_ReaderScreenState` (init/dispose, scroll logic, scroll-to-ayah deep-linking, `lastAyahs` cache)
- `_SingleScrollMushaf` (Mushaf-область, scroll detection)
- `_AyahSeparator` (OrnateDivider)
- `_HoverToggle` (панель управления top/bottom)
- `_BookmarkedToast`
- `_MoreOptionsSheet`

Все классы в одном файле по разным причинам — privacy (но они могли бы быть в отдельном `widgets/`). Самое серьёзное — `_checkScrollEnd` **не throttle'd** (строки 280-299):

```dart
void _checkScrollEnd() {
  if (!_pageCtrl.hasClients) return;
  if (_lastAyahs == null || _lastAyahs!.isEmpty) return;
  final position = _pageCtrl.position;
  if (position.maxScrollExtent > 0 &&
      position.maxScrollExtent - _pageCtrl.offset <
          position.viewportDimension) {
    final lastAyah = _lastAyahs!.last;
    if (_lastReportedAyahNumber != lastAyah.ayahNumber) {
      _lastReportedAyahNumber = lastAyah.ayahNumber;
      final repo = ref.read(quranRepositoryProvider);
      unawaited(repo.recordLastRead(
        surahId: widget.surahId,
        ayahId: lastAyah.id,
      ));
    }
  }
}
```

Проблема: на каждом scroll-frame Flutter отправляет десятки событий. Даже с guard `_lastReportedAyahNumber != lastAyah.ayahNumber`, **listener вызывается на каждый scroll-tick** (scroll-jump -> 5-10 fps, scroll-fling -> 60-90 fps). Хотя запись в БД защищена guard, **listener'd callback потребляет CPU**.

Решение:
1. Throttle через `StreamController<DateTime>` + debounce 200ms.
2. Или очищать listener на dispose (это уже есть, но перфоманс на слабых устройствах страдает).

### B2. `initState` имеет 4 вложенных `addPostFrameCallback` (строки 142-227)

```dart
void initState() {
  super.initState();
  _readingMode = ref.read(appPreferencesProvider).readingMode;
  // 1) addPostFrameCallback #1: ensureLoaded (Round 9.2B)
  WidgetsBinding.instance.addPostFrameCallback((_) { ... });

  _pageCtrl.addListener(_checkScrollEnd);
  // 2) addPostFrameCallback #2: record last + initial scroll
  WidgetsBinding.instance.addPostFrameCallback((_) async { ... });
  // 3) addPostFrameCallback #3 (вложен): scrollToAyah (next frame)
  WidgetsBinding.instance.addPostFrameCallback((_) { ... });  
}
```

4 добавления frameCallback = 4 future-фрейма перед первым UI-инпутом. **Это можно** объединить в **один onAyahsLoaded callback** через `ref.listenManual`.

## 2. Серьёзные (Critical)

### C1. Magic `tileExtent = 220.0` в 3 местах

**Файл:** `lib/features/quran/presentation/reader_screen.dart` (строки 213, 266)

```dart
// строка 213 (deep-link initState fallback)
const tileExtent = 220.0;
final target = (idx * tileExtent - viewport / 2 + tileExtent / 2)
    .clamp(0.0, maxOffset);

// строка 266 (_scrollToAyah)
void _scrollToAyah(int index) {
  const tileExtent = 220.0;
  final target = (index * tileExtent).clamp(...);
}
```

Магическое `220.0` повторяется **дважды**. При несовпадении — buggy scroll. Нужна named constant:

```dart
class _ReaderScreenState extends ConsumerState<ReaderScreen> {
  /// Эмпирическая высота одного `AyahTile` в логических пикселях.
  /// Используется только при deep-link scroll (initState → build
  /// race). После первого build предпочитаем `_tileKeys[idx].currentContext`
  /// + RenderBox.localToGlobal.
  static const _kAyahTileExtent = 220.0;
  // ... использовать везде
}
```

### C2. GlobalKey мутация на каждый surahId

**Файл:** `lib/features/quran/presentation/reader_screen.dart:108`

```dart
final GlobalKey _mushafKey = GlobalKey();
```

Но планируется `ValueKey(surahId)` (`mushafKey` пересоздаётся) — это в комментарии. **НО** `_mushafKey` — **static**, не `final ValueKey`. Каждый hot reload / rebuild может утечь `GlobalKey`.

### C3. `applyNameOverrides` N+1 update в цикле

**Файл:** `lib/features/audio/data/reciters_repository.dart:397-419`

```dart
Future<int> applyNameOverrides() async {
  final all = await _dao.getAll();
  var fixed = 0;
  for (final r in all) {
    final id = r.mp3quranId;
    if (id == null) continue;
    final override = kReciterRuNames[id];
    String? newName;
    if (override != null) {
      newName = override;
    } else if (looksLikeBrokenRussian(r.nameRu ?? '')) {
      newName = r.nameEn;
    }
    if (newName != null && newName != r.nameRu) {
      await _dao.updateNameRu(r.id, newName);  // ← N+1 round-trips
      fixed += 1;
    }
  }
  return fixed;
}
```

For 240 reciters = 240 round-trips. Можно батчить через `db.batch((b) => { ... })`. Drift `_dao.batch((b) => b.updateWhere(...))` сделает это одной транзакцией.

### C4. `_lastTafsirSourceId` — in-memory без персиста

**Файл:** `lib/features/quran/presentation/widgets/tafsir_panel.dart:45`

```dart
final _lastTafsirSourceId = <int, int>{};
```

Global mutable, теряется на cold restart. Противоречит принципу "пользователь не теряет данные".

### C5. `_readingMode` mutable state мимо Riverpod (race condition)

**Файл:** `lib/features/quran/presentation/reader_screen.dart:124, 137`

```dart
late String _readingMode;
...
_readingMode = ref.read(appPreferencesProvider).readingMode;
```

`readingMode` в prefs, **но** Riverpod не watch'ed — пользователь в Settings меняет режим, Reader не обновляется. Это известная проблема (`// Не через ref.watch — см. комментарий в _readingMode`). Фикс через `ref.listen` с `setState`.

### C6. `AyahTile._loadWords` — race condition между token и mounted

**Файл:** `lib/features/quran/presentation/widgets/reader_widgets.dart:88-98`

```dart
Future<void> _loadWords() async {
  final token = ++_loadToken;
  setState(() => _loadingWords = true);
  final list = await ref.read(...).wordsForAyahViaWordsDao(widget.ayah.id);
  if (!mounted || token != _loadToken) return;
  setState(() {
    _words = list;
    _loadingWords = false;
  });
}
```

`mounted && token != _loadToken` — if dispose happened, we skip setState. **OK**. Но если `didUpdateWidget` срабатывает И dispose происходит между query и setState — `token != _loadToken` это ловит. **OK**.

Однако проблема: если `widget.ayah.id` остался тем же (пользователь обновил только translation), `didUpdateWidget` НЕ вызывает `_loadWords` повторно. **Это OK** — words не изменились.

### C7. `_SingleScrollMushaf._AyahSeparator` magic: первый аят NO divider

**Файл:** `lib/features/quran/presentation/reader_screen.dart`

Из комментария в reader_widgets.dart:108-109:
```dart
// OrnateDivider тоже НЕ здесь — разделитель между аятами
// рисует [_SingleScrollMushaf._AyahSeparator] в `reader_screen.dart`,
// чтобы можно было пропустить divider перед первым аятом.
```

Проверка «index == 0» вложена в JSX render. Лучше `_AyahSeparator`-параметризовать через `showDivider: bool`.

### C8. `kPreviewHeight = 280` magic constant

**Файл:** `lib/features/reader_settings/presentation/reader_display_settings_screen.dart:44`

```dart
/// Размер 280px подобран эмпирически: при экстремальных значениях
/// (fontSize 40 + lineHeight 2.6) внутри помещается:
const double kPreviewHeight = 280;
```

Эта константа используется как верхний padding ListView **и** как height в Positioned sticky preview. Если fontSize/lineHeight поменяются в defaults — константа устареет. Лучше вычислять через `MediaQuery + scale`.

## 3. Незначительные (Minor)

### M1. `_kTotalAyahs = 6236` hardcoded constant

**Файл:** `lib/features/statistics/presentation/statistics_screen.dart:61`

```dart
static const int _kTotalAyahs = 6236;
static const int _kTotalSurahs = 114;
```

Это правильное число (Total ayahs в Hafs mushaf), но лучше read из БД `COUNT(*) FROM ayahs` (с round). Иначе при изменении seed (например, добавится 114ая сура) — statistics сломается. Лучше — кешированный `Provider` через `(SELECT COUNT(*) FROM ayahs)`.

### M2. `_readerDataProvider` имеет `autoDispose` без явной причины

**Файл:** `lib/features/quran/presentation/reader_screen.dart:26`

```dart
final _readerDataProvider = FutureProvider.autoDispose
    .family<ReaderData, ReaderKey>(...);
```

`autoDispose` здесь для memory-leak prevention (при выходе из Reader освобождается кеш). Но `loadReaderDataByTranslator` уже на DB-уровне (быстрый). Возможно, `autoDispose` overengineering.

### M3. `appPreferencesProvider` settings migrate при каждом вызове `displaySettings`

**Файл:** `lib/core/storage/app_preferences.dart:121-148`

`get displaySettings` каждый раз делает `codec.decode(null).copyWith(...)` — ребилдит объект на **каждом** `ref.watch(appPreferencesProvider).displaySettings`. Кеширование через `late final`.

### M4. `reader_widgets.dart` — `_loadingWords = true; setState(...)` — оба сразу

**Файл:** `lib/features/quran/presentation/widgets/reader_widgets.dart:88-90`

Можно объединить через `setState(() { _loadingWords = true; ... })` (но фактически это уже сделано).

### M5. `kPreviewHeight = 280` зависит от default Settings

**Файл:** `lib/features/reader_settings/presentation/reader_display_settings_screen.dart:44`

Если defaults fontSize=28, lineHeight=2.4 — высота аята ~110px (а не 220 как в Mushaf). `kPreviewHeight` подобран для ектремальных значений, не defaults — sticker preview выглядит странно для defaults.

### M6. `_lastTafsirSourceId` Map has no upper bound

**Файл:** `lib/features/quran/presentation/widgets/tafsir_panel.dart:45`

`<int, int>{}` без capacity. Если пользователь taps 1000 разных аятов → 1000 entries. Memory leak risk.

### M7. `_checkScrollEnd` has no debounce

**Файл:** `lib/features/quran/presentation/reader_screen.dart:280`

На каждом scroll-tick listener вызывается. Хотя запись в БД guarded, **listener callback` consumes CPU на каждое pixel-scroll**. Нужно debounce через `Stream.debounce()`.

### M8. `AyahTile` rebuilds on every ayahs-stream-update

**Файл:** `lib/features/quran/presentation/widgets/reader_widgets.dart:101`

`build()` зависит от `widget.ayah.id`. Если stream emit'ит с тем же `ayah.id` (например, change в `isBookmarked`) — `_AyahTileState.didUpdateWidget` срабатывает, но не пересчитывает words. **OK**.

### M9. `search_screen.dart:21` — `setState` при каждом keystroke

**Файл:** `lib/features/search/presentation/search_screen.dart:52`

```dart
onChanged: (v) => setState(() => _query = v),
```

Каждый keystroke = full widget rebuild. Уже отмечалось в Part 1 review. Можно вынести `_SearchResults` в отдельный widget.

### M10. `main_scaffold.dart` Background `CustomPaint` — нет Skip-логики

**Файл:** `lib/shared/widgets/main_scaffold.dart:44`

```dart
Positioned.fill(child: CustomPaint(painter: _ScaffoldTexturePainter()))
```

`_ScaffoldTexturePainter` рисует каждый кадр для всей Stack. `_shouldRepaint` всегда возвращает `true` (default). Нужно `return oldDelegate == this;` или Skip-флаг.

### M11. `reciters_repository.dart:32` — `lastIndexOf` для одной строки

**Файл:** `lib/features/audio/data/reciters_repository.dart:144`

`final sep = s.lastIndexOf(' - ');` — это OK, но `s.indexOf(' - Murattal')` было бы быстрее. Мало влияния.

### M12. `reciters_repository.dart:152` — list of markers

**Файл:** `lib/features/audio/data/reciters_repository.dart:152`

```dart
final cutMarkers = [' по цепочке ', " Men Tariq ", ' - Men '];
for (final m in cutMarkers) {
  final i = s.indexOf(m);
  if (i > 0) s = s.substring(0, i);
}
```

Каждый iter делает full String scan. Для длинного rewaya (100+ chars) — O(N × M) where M=markers. Малый impact, но `RegExp` будет O(N+M).

## 4. Рекомендации (Recommendations)

### R1. Разделить `reader_screen.dart` на 5+ widget'ов

`reader_screen.dart` (2414 строк) должен быть:
- `reader_screen.dart` — orchestration (300-400 строк)
- `widgets/mushaf_scroll.dart` — `_SingleScrollMushaf` + `_AyahSeparator` (700 строк)
- `widgets/reader_palette_sheet.dart` — `_HoverToggle` + `_MoreOptionsSheet` (350 строк)
- `widgets/reader_navigation.dart` — deep-link / page-page (200 строк)
- `widgets/bookmark_toast.dart` — `_BookmarkedToast` (100 строк)

### R2. Throttle `_checkScrollEnd` через `Stream.debounce(200ms)`

```dart
final _scrollEndTrigger = _pageCtrl.positionStream;

// или явный throttle:
Timer? _scrollEndTimer;
void _scheduleScrollEnd() {
  _scrollEndTimer?.cancel();
  _scrollEndTimer = Timer(Duration(milliseconds: 200), _checkScrollEnd);
}
```

### R3. Memoize `displaySettings` в `AppPreferences`

```dart
late final ReaderDisplaySettings _displaySettings =
    _computeDisplaySettings();

ReaderDisplaySettings get displaySettings => _displaySettings;
```

### R4. Извлечь magic constants в named статики

В `reader_screen.dart`:
- `static const _kAyahTileExtent = 220.0`
- `static const _kScrollEndDebounceMs = 200`
- `static const _kScrollEndThreshold = 1.0` (1 viewport)

### R5. Persist `_lastTafsirSourceId` в SharedPreferences

Ключ `tafsir.lastSourceId_${ayah.id}` или `tafsir.lastSourceId` (последний global). При cold start — сохраняется.
