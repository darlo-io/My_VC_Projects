### ✅ Фаза 2 (Lazy load в Reader) — ЗАВЕРШЕНА (2026-07-28)

**Файлы**:
- `lib/features/quran/data/ayahs_service.dart` — новый `AyahsService` с `ensureLoaded(surahId)`
- `lib/features/quran/data/ayahs_service.dart` — `AyahsSyncState` (UI state)
- `lib/core/database/daos/ayah_dao.dart` — `countAyahs(surahId)` для проверки lazy fetch
- `lib/app/providers.dart` — `ayahsServiceProvider`, `ayahsSyncStateProvider`
- `lib/features/quran/presentation/reader_screen.dart` — `addPostFrameCallback` в initState

**Логика работы**:
```dart
WidgetsBinding.instance.addPostFrameCallback((_) {
  ref.read(ayahsServiceProvider).ensureLoaded(widget.surahId);
});
```

`ensureLoaded`:
1. `countAyahs(surahId)` — уже загружены?
2. `_hasMissingMetadata(surahId)` — page IS NULL (cold install через quran_full.json)?
3. Если да или count == 0 → `_fetchAndInsert(surahId)` (2 параллельных Dio calls)
4. Сохраняет через `UPDATE ayahs SET page=?, juz=?, hizb=? WHERE surah_id=? AND ayah_number=?`

**Тест на устройстве (Round 9.2B финал)**:
- Cold install: 7 аятов Аль-Фатиха с page IS NULL
- Открыл Reader → `ensureLoaded` запустился
- Lazy fetch: 2 параллельных запроса (uthmani + by_chapter)
- UPDATE в БД: `page=1, juz=1, hizb=1` для всех 7 аятов
- DB query после fetch: `id=1 surah_id=1 ayah_number=1 page=1` ✅

### Баг исправленный (critical)
Round 9.2B изначально использовал `INSERT OR IGNORE` — это создавало дубликаты строк (auto-increment id), потому что таблица `ayahs` НЕ имеет UNIQUE constraint на (surah_id, ayah_number), только PRIMARY KEY. После замены на `UPDATE` — правильно обновляет существующие строки.
