### B2. Race condition + отсутствие transaction в `recordReview` — `learning_dao.dart:92-123`

**Файл:** `lib/core/database/daos/learning_dao.dart:92-123`

```dart
final existing = await (select(learningWords)
      ..where((l) => l.wordId.equals(wordId)))
    .getSingle();  // ← NON-TRANSACTIONAL
final next = Sm2.next(...);
await (update(learningWords)
      ..where((l) => l.id.equals(existing.id)))
    .write(...);  // ← NON-TRANSACTIONAL
return (select(learningWords)..where((l) => l.id.equals(existing.id)))
    .getSingle();
```

**3 проблемы**:
1. **Three separate DB calls, no transaction**. Если между `getSingle()` и `update()` другой процесс добавит/удалит запись — race condition.
2. **`getSingle()`-без-`getSingleOrNull()`** — упадёт с `StateError` (TooManyResults/NoElement), если запись была удалена между двумя вызовами. В LearningDao `wordId` UNIQUE, но если `removeWord` сработал параллельно — exception.
3. **`write()` следует без `changes`-проверки**. Если во время UPDATE запись удалена — вернёт 0, но без `where` это no-op.

**Исправление** — atomic transaction:

```dart
Future<LearningWord> recordReview({
  required int wordId,
  required ReviewQuality quality,
  DateTime? now,
}) async {
  assert(quality >= 0 && quality <= 5, 'quality must be 0..5');
  final ts = now ?? DateTime.now();
  return await transaction(() async {
    final existing = await (select(learningWords)
          ..where((l) => l.wordId.equals(wordId)))
        .getSingleOrNull();
    if (existing == null) {
      throw StateError('No LearningWord row for wordId=$wordId');
    }
    final next = Sm2.next(
      easeFactor: existing.easeFactor,
      intervalDays: existing.intervalDays,
      repetitions: existing.repetitions,
      quality: quality,
      now: ts,
    );
    await (update(learningWords)
          ..where((l) => l.id.equals(existing.id)))
        .write(LearningWordsCompanion(
          status: Value(next.status),
          easeFactor: Value(next.easeFactor),
          intervalDays: Value(next.intervalDays),
          repetitions: Value(next.repetitions),
          nextReviewAt: Value(next.nextReviewAt),
          lastReviewAt: Value(ts),
        ));
    return (select(learningWords)..where((l) => l.id.equals(existing.id)))
        .getSingle();
  });
}
```

### B3. SQLite ловит поломанный FTS5 query — `search_dao.dart:100-118`

**Файл:** `lib/core/database/daos/search_dao.dart:100-118`

```dart
String _sanitizeFtsQuery(String raw) {
  final trimmed = raw.trim();
  if (trimmed.isEmpty) return '';

  final escaped = trimmed
      .replaceAll('"', '""')   // ← escape кавычек
      .replaceAll("'", '');    // ← удаление одинарных

  final tokens = escaped.split(RegExp(r'\s+'));
  if (tokens.isEmpty) return escaped;
  final last = tokens.last;
  if (!last.endsWith('*') && !last.contains(':')) {
    tokens[tokens.length - 1] = '$last*';
  }
  return tokens.join(' ');
}
```

**Проблема**: двойная sanitization. Sanitize в `search_dao.dart:100-118` И в `fts_query.dart:35-50` (`buildFtsPrefixQuery`). Это разные функции с разной логикой:
- `search_dao._sanitizeFtsQuery` — `replaceAll('"', '""')` сохраняет кавычки.
- `buildFtsPrefixQuery` — `.where((c) => !banned.contains(c)).join()` удаляет кавычки.

**Может привести к**:
- FTS5 SQL Injection: если обе функции sanitize, но по-разному, итоговый query может оказаться синтаксически некорректным → SQLite throws `SqliteException: fts5: syntax error`.
- В contenteditable UI пользователь вводит `"тест'` → sanitizer 1 выдаёт `тест`, sanitizer 2 выдаёт `тест`, итог ОК. Но ввод `(тест)` → sanitizer 1 выдаёт `(тест)`, sanitizer 2 выдаёт `тест` (потому что `(` в banned). Конфликт.

**Где дёргается**: `ayah_dao.dart:233` использует `buildFtsPrefixQuery`, `search_dao.dart:100` использует `_sanitizeFtsQuery`. Две функции → один FTS5 — гарантия recurring bugs.

**Исправление**: Удалить `_sanitizeFtsQuery` в `search_dao.dart`, использовать `buildFtsPrefixQuery` (которая centralized в `fts_query.dart`).

### C2. `_sanitizeFtsQuery` дублирует `buildFtsPrefixQuery` — `search_dao.dart:100-118`

См. B3. Серьёзный потому что в одной функции `_sanitizeFtsQuery` логика **противоречит** `buildFtsPrefixQuery`:

- `_sanitizeFtsQuery`: `replaceAll('"', '""')` (escape) — это syntax для FTS5 phrase query.
- `buildFtsPrefixQuery`: `.split('').where((c) => !banned.contains(c)).join()` (delete) — это character removal.

Эти стратегии **взаимоисключающие**. Результат — query содержит либо двойные кавычки (escape), либо без (delete), в зависимости от того, кто последний sanitized.

### C4. Verify-кейс `streak>` 0 НЕ проверяет реальность чтения — `position_dao.dart:201-235`

```dart
Stream<int> watchStreakDays({DateTime? now}) {
  // ...
  while (true) {
    final key = _isoDate(cursor);
    final read = byDate[key] ?? 0;
    if (read == 0) {
      if (streak == 0 && _isoDate(cursor) == _isoDate(today)) {
        cursor = cursor.subtract(const Duration(days: 1));

  }
```

### C6. `QuizSession.fromTranslations` имеет `distractor` race condition — `quiz_session.dart:200-218`

```dart
final distractorIndices = List<int>.generate(pool.length, (j) => j)
  ..shuffle(rng);
final distractors = <TranslationOption>[];
for (final j in distractorIndices) {
  if (j == i) continue;
  if (distractors.length == optionsPerQuestion - 1) break;
  distractors.add(pool[j]);
}
```

**Проблема**: при маленьком `pool` (4–6 элементов) — мы берём все элементы КРОМЕ `i`, но `break` по `distractors.length == 3`. Если pool = 4, distractor pool = 3, OK. Если pool = 5, distractor pool = 4, OK. Если pool = 8, distractor pool = 3, OK.

**Но**: `assert(pool.length >= 4)` срабатывает только при `minPoolSize = 4`. Для edge case pool = 4 — distractors = 3, OK. Нет багов.

**Однако**: `correctIndex = allOptions.indexOf(correct)` после `shuffle` — если `correct` не в `allOptions` (из-за deduplication?) — `indexOf` вернёт -1. Защита: `assert(distractors.length == 3)` и `allOptions.length == 4`, что строго гарантирует `correct` ∈ `allOptions`.

**ОК сейчас, но**: при добавлении dedup logic (если будем удалять дубликаты) — `indexOf` может вернуть -1. Recommend defensive: `final correctIndex = allOptions.indexOf(correct); assert(correctIndex >= 0, 'correct must be in options');`.

### C11. `migration` strategy hardcoded `from < N` — `app_database.dart:114-352`

Каждое новое обновление добавляет `if (from < N)` блок. При `from = 18` (current) — все blocks выполнятся. При `from = 5` — все 4-block'а выполнятся. Это правильно (additive forward-compatible).

**Но**: naming convention не выдержан. `v9 -> v10` block использует `m.addColumn(reciters, reciters.mp3quranId)`. **Pre-v9** installs (`from < 9`) — `reciters` table создаётся без `mp3quranId`, но **v9 -> v10** block добавит его. OK.

**Проблема**: `if (from < 8)` block содержит `DELETE FROM learning_words` и `CREATE UNIQUE INDEX`. Если `from = 5` (pre-v8), этот block **ПОСЛЕ** `if (from < 7)` срабатывает. OK.

**Проблема реальная**: `if (from < 5)` блок вызывает `_resetSchema(m)` — **полностью пересоздаёт schema**. Это правильно для pre-v5, но для **v5+** user data должна сохраняться. Контракт в dartdoc соблюдается (`if (from < 5)`), но **легко** сделать bug при bump'е `schemaVersion` в будущем.

**Рекомендация**: добавить runtime assertion `assert(from >= 5 || _resetSchemaCalled, ...)` или разделить v5-and-new vs v5-and-old на два `MigrationStrategy` callable.
