# QURAN APP — ПЛАН РЕАЛИЗАЦИИ

Документ основан на `docs/ARCHITECTURE.md` (v2.2) и описывает порядок реализации приложения, разбитый на инкрементные фазы. Каждая фаза завершается работающим билдом, пригодным для проверки на устройстве.

---

## 0. Глобальные цели

| Цель | Результат |
| --- | --- |
| Offline First | Все ключевые функции работают без сети |
| Content Decoupling | Контент обновляется без релиза приложения |
| Cache First | Повторные запросы используют локальный кеш |
| Modular Architecture | Изолированные фичи с чёткими границами |
| Word-Level Learning | Каждое слово кликабельно, со своим контекстом |

---

## 1. Технологический стек (целевой)

- **Flutter 3.x**, Dart ≥ 3.3
- **Riverpod 3.x** — DI, состояние, side-effects
- **go_router** — навигация и deep links
- **Drift** + `sqlite3_flutter_libs` — основное хранилище
- **Dio** — HTTP, ретраи, скачивание
- **just_audio** + **audio_service** — плеер и фоновое воспроизведение
- **workmanager** — фоновые задачи (prefetch, sync, cache GC)
- **shared_preferences** — простые пользовательские настройки
- **path_provider** — пути к кешу и базам
- **crypto** (SHA-256) — целостность
- **cryptography / ed25519** — подпись контента
- **package_info_plus** — версия приложения (для манифеста)
- **intl** — форматирование дат/чисел
- **dio_cache_interceptor** *(опционально)* — HTTP-кеш

## 3. MVP v0.1 — Чтение (2–3 месяца)

Цель: пользователь может читать Коран, ставить закладки, делать базовый поиск.

### 3.1 Фундамент

- [ ] Инициализация Flutter-проекта, настройка линтеров, тем, локализации
- [ ] Подключение Riverpod, go_router, Drift, Dio, shared_preferences
- [ ] Структура `core/` и `features/` согласно §2
- [ ] Базовый `AppRouter` с shell-маршрутами (Home, Search, Bookmarks, Settings)
- [ ] Сборка debug APK / iOS build

### 3.2 База данных (Drift)

- [ ] Описать таблицы `surahs`, `ayahs`, `words`, `translators`, `translations`, `bookmarks`, `last_position`, `reading_history`
- [ ] `@DriftDatabase(version: 1)` + явная стратегия миграций
- [ ] DAO: `SurahDao`, `AyahDao`, `BookmarkDao`, `LastPositionDao`, `ReadingHistoryDao`
- [ ] Сидинг из bundled-ассетов (`assets/db/quran_v1.sqlite`)

### 3.3 Контент и доставка

- [ ] Встроить минимальный базовый набор: текст утхмани, 1 перевод (например, ru.Кулиев)
- [ ] Подготовить ассеты: `surahs.json`, `ayahs.json`, `translations.json`
- [ ] CLI-скрипт (Dart) для генерации `quran_v1.sqlite` из JSON

### 3.4 UI чтения

- [ ] Экран списка сур
- [ ] Экран чтения суры с пагинацией (страница mushaf, джуз)
- [ ] Список джузов с прогрессом
- [ ] Кнопка закладки + список закладок
- [ ] Сохранение `last_position` при выходе
- [ ] Запись `reading_history` по мере чтения

### 3.5 Поиск (FTS5, базовый)

- [ ] Нормализация арабского (харакаты, алеф-варианты, NFC)
- [ ] FTS5-таблицы: `ayahs_fts`, `translations_fts`
- [ ] UI поиска: единое поле, фильтр по арабскому/переводу
- [ ] Подсветка совпадений в сниппете

### 3.6 Настройки

- [ ] Тема (light/dark/system)
- [ ] Размер арабского шрифта
- [ ] Включение/отключение перевода
- [ ] Сохранение в `shared_preferences`

### 3.7 Definition of Done MVP v0.1

- Чтение любой суры с переводом, закладками, поиском работает офлайн после первого запуска
- `flutter test` зелёный, ключевые виджеты покрыты golden-тестами

## 4. MVP v0.2 — Аудио (+ 1–2 месяца)

Цель: воспроизведение аудио с подсветкой текущего аята и офлайн-кешем.

### 4.1 Аудио-инфраструктура

- [ ] `core/audio/AudioPlayerController` на базе `just_audio` + `audio_service`
- [ ] `AudioCacheService` (поиск в `getApplicationSupportDirectory()/audio_cache/<reciter>/`)
- [ ] `AudioDownloadService` на базе Dio: `cancelToken`, прогресс, ретраи
- [ ] LRU GC: при превышении лимита удалять файлы с минимальным `last_played_at`

### 4.2 Контент

- [ ] Манифест `audio_sources.json` (primary/backup/archive.org)
- [ ] Цепочка источников с автоматическим fallback
- [ ] Таблицы `reciters`, `audio_cache_metadata`, миграция БД до v2
- [ ] Минимум 2 чтеца (mishari + sudais)

### 4.3 UI

- [ ] Bottom mini-player и расширенный экран плеера
- [ ] Выбор чтеца в настройках аудио
- [ ] Список загруженных сур / джузов с прогрессом и кнопкой «удалить»
- [ ] Настройка лимита кеша (по умолчанию 2 GB)

### 4.4 Прочее

- [ ] Фоновое воспроизведение (lock screen, notification) через `audio_service`
- [ ] Обработка ошибок: 3 источника → кеш → сообщение пользователю
- [ ] Телеметрия прослушивания → `reading_history`

### 4.5 Definition of Done MVP v0.2

- Плеер играет любую суру, показывает обложку/имя чтеца, переключает рецитера
- Загрузка суры + удаление работают; LRU-вытеснение валидируется тестом
- Фоновое воспроизведение не убивается системой

## 5. MVP v0.3 — Слова (+ 1–2 месяца)

Цель: интерактивная работа со словами и личный словарь.

### 5.1 Данные

- [ ] Расширить таблицу `words` (translation / lemma / root уже в схеме v1)
- [ ] Импорт словаря (базовый перевод слов) из bundled-ассета
- [ ] Таблицы `learning_words` (SM-2 поля), миграция БД до v3

### 5.2 Word timings

- [ ] Контент-файл `word_timings.json` по чтецам
- [ ] `word_timings` DAO + репозиторий
- [ ] Конвертер JSON → БД при загрузке контента

### 5.3 UI

- [ ] Кликабельные слова в аятах → `WordCardSheet` (слово, перевод, корень, лемма, ▶)
- [ ] Подсветка текущего слова во время воспроизведения
- [ ] Экран «все вхождения слова» (список аятов)
- [ ] Личный словарь (список избранных/изучаемых)
- [ ] Воспроизведение слова: `seek(start_ms)` → `play()` → `stop(end_ms)`
- [ ] Повтор слова x3 / x5 / x10, повтор аята, A-B repeat (опорный функционал для Hifz)

### 5.4 Definition of Done MVP v0.3

- Тап по слову открывает карточку; воспроизведение слова работает
- Подсветка слова синхронна с аудио (±50 мс)
- Личный словарь сохраняется, поддерживает добавление/удаление

- [ ] Firebase Auth (анонимный/email/google)
- [ ] Firestore: документы пользователя (`bookmarks`, `notes`, `learning_words`, `settings`, `last_position`)

## 12. Риски и компромиссы

| Риск | Митигация |
| --- | --- |
| Большой объём встроенного контента | Только базовые ассеты в APK, остальное — через Content Update |
| Лимиты CDN | Цепочка источников + archive.org как fallback |
| Сложность SM-2 на малых данных | A/B-режимы, накопление данных перед строгим расписанием |
| Миграции Drift при эволюции схемы | Все миграции явно описаны, тесты сценариев upgrade с фикстур |
| FTS5 и арабский — edge cases | Отдельный модуль нормализации с юнит-тестами на 100+ примерах |
| Размер аудио-кеша | LRU + лимит, явный UX управления |

## 13. Definition of Done для всего приложения

- Полная функциональность без сети (после первой синхронизации контента)
- Все таблицы БД имеют миграции и покрыты тестами
- Подсветка слов и A-B Repeat синхронны с аудио
- LRU-вытеснение работает корректно (авто-тест)
- Целостность контента проверяется (SHA-256 + ED25519)
- Rollback контента протестирован на смоделированной ошибке
- Crash-free sessions ≥ 99.5% на тестовом контингенте
- a11y-чеклист пройден для ключевых экранов
