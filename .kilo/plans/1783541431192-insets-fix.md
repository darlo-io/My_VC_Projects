# Round 9.9 — Insets Fix для Flutter Scaffold (BOTTOM OVERFLOWED in landscape)

**Дата:** 2026-08-01
**Предшествующий план:** разбор insets в Android (предыдущее сообщение)
**Цель:** Исправить `BOTTOM OVERFLOWED BY 25 PIXELS` в landscape на Home Screen и других экранах `MainScaffold`, путём корректного `SafeArea` для landscape navigation bar.

---

## Корневая причина

В landscape с 3-button navigation bar Android размещает nav bar **справа** (не снизу). `MainScaffold.bottomNavigationBar` уже адаптируется автоматически (его высота в landscape становится шириной в правой зоне). Однако `body` (HomeScreen и др.) рендерится на **полную ширину** включая зону за nav bar.

**Текущий код** `lib/features/home/presentation/home_screen.dart:91`:
```dart
SafeArea(
  bottom: false,  // ← намеренно отключён, т.к. bottomNavBar уже учёл bottom
  child: ListView(...),
)
```

`bottom: false` означает **НЕ учитывать bottom inset**, но `top`/`left`/`right` всё равно учитываются. **Но в landscape при 3-button nav bar — bottom inset всё равно учитывается**, так что SafeArea корректно работает для bottom. **Однако он НЕ учёл right inset**, который в landscape указывает на правую nav bar.

В portrait (1080×2376, 3-button nav внизу):
- top: ~32dp (status bar) — учтён
- bottom: ~48dp (nav bar) — НЕ учтён (но учтён в bottomNavigationBar)
- left/right: 0dp — OK

В landscape (2376×1080, 3-button nav справа):
- top: ~32dp (status bar) — учтён
- bottom: ~24dp (gesture bar — даже если 3-button, в landscape кнопки справа) — НЕ учтён
- right: ~48dp (nav bar) — **НЕ учтён → BOTTOM OVERFLOWED BY 25 PIXELS** на grid'е категорий

## Решение

Заменить `SafeArea(bottom: false)` на `SafeArea(top: false, bottom: false)`:
- `top: false` — не дублировать status bar (учитывается в AppBar/Container)
- `bottom: false` — не дублировать nav bar (учитывается в bottomNavigationBar)
- `left: true, right: true` (defaults) — учитывать display cutout **И** landscape nav bar справа

Это минимально-invasive фикс — 2 строки изменений.

## Возможные блокеры / вопросы

**Q1: `SafeArea(top: false, bottom: false)` работает на Android 11+/15+?**
Flutter `SafeArea` использует `MediaQuery.padding` который устанавливается автоматически через `WindowInsetsCompat`. На Android 15+ с `targetSdk=36` (наш случай) edge-to-edge обязателен → `padding.right/left` **возвращают реальные значения** для landscape nav bar. Должно работать.

**Q2: Не сломает ли это portrait с 3-button nav?**
Нет. В portrait:
- right: 0dp (нет cutout/nav bar справа)
- left: 0dp
- top: false → не учитываем (Container/_Header учитывает сам)
- bottom: false → не учитываем (bottomNavBar учитывает)

Поведение portrait остаётся идентичным. Поведение landscape — становится правильным.

**Q3: А как насчёт edge-to-edge gesture bar (24dp gesture)?**
В Flutter `MediaQuery.padding` всегда содержит `bottom: 24` для gesture bar (Android 10+). Если установить `bottom: true` в SafeArea — будет двойной отступ (наш bottomNavBar уже учёл). Если `bottom: false` — в portrait/landscape без 3-button nav content будет уходить за gesture bar.

Решение для этого edge-case — в `MainScaffold.bottomNavigationBar` bottom inset обрабатывается один раз. Для нашего фикса не трогаем.

## Что НЕ делается (out of scope)

- Полная insets-архитектура (`MediaQuery.viewInsets`, `useSafeArea` в Compose-стиле) — слишком большой рефакторинг.
- Удаление `MiniPlayer` (он сейчас над bottomNavigationBar в MainScaffold и занимает место).
- Изменение layout landscape vs portrait (например, side-by-side grid для landscape).
- Display cutout handling (есть notch в landscape) — auto handled by SafeArea left/right.
- IME insets — текущие настройки клавиатуры работают корректно (см. settings/search).

## Альтернатива (если минимальный fix не работает)

Если `SafeArea(top: false, bottom: false)` не решает (например, если `MainScaffold` имеет специальный handling для nav bar), альтернативные варианты:

**Вариант A**: явный padding на right:
```dart
final rightInset = MediaQuery.of(context).padding.right;
Padding(
  padding: EdgeInsets.only(right: rightInset),
  child: ListView(...),
)
```

**Вариант B**: обернуть home в `MediaQuery.removePadding` если padding уже учтён на parent уровне — но это не наш случай.

**Вариант C**: использовать `Scaffold(resizeToAvoidBottomInset: false)` + bottomSheet — слишком invasive.

Будем пробовать **простой SafeArea вариант сначала**. Если не сработает — перейдём к Варианту A.
