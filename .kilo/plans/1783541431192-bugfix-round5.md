# quran_app — Bugfix round 5 (2026-07-22)

User-reported bug (2026-07-22):
> При первом запуске приложения всё работает правильно. Поворот
> экрана есть только на экране чтения, но после выхода с экрана
> чтения, поворот экрана срабатывает и на других экранах.

## Анализ root cause

В Round 4 per-widget логика в `ReaderScreen`:
```dart
@override
void initState() {
  super.initState();
  WidgetsBinding.instance.addPostFrameCallback((_) async {
    await SystemChrome.setPreferredOrientations(_allOrientations);
  });
  ...
}

@override
void dispose() {
  _pageCtrl.dispose();
  unawaited(SystemChrome.setPreferredOrientations(_portraitOnly));  // ← проблема!
  super.dispose();
}
```

**Почему первый раз работал, а второй — нет**:

`unawaited(SystemChrome.setPreferredOrientations(_portraitOnly))` ставит
Future в очередь ПОСЛЕ `super.dispose()`. На первом проходе это
могло сработать, потому что Android Activity была в landscape режиме
и изменения применялись сразу. На втором проходе:
1. Reader mounted → initState fires → landscape activated
2. Reader popped → dispose fires → `unawaited` schedules Future
3. `super.dispose()` убирает widget из дерева
4. Future пытается выполниться, но **новый route уже на mounted'е**
5. Android Activity получает race между старой и новой
   orientation — и остаётся в landscape

## Решение: глобальный `OrientationGuard`

Удалил per-widget логику. Создал глобальный service `OrientationGuard`,
который слушает **top-route через `routerDelegate.addListener`** в
`app_router.dart`. Listener срабатывает на каждом push/pop/replace,
гарантированно синхронно обновляя ориентацию ДО того, как новый route
начнёт монтироваться.

### Файлы

**Новый (1)**:
- `lib/app/orientation_guard.dart` — `OrientationGuard` class +
  `globalOrientationGuard` singleton с `setIsReader(bool)` методом.
  Внутри — синхронный вызов `SystemChrome.setPreferredOrientations`.

**Изменены (3)**:
- `lib/app/router/app_router.dart` — добавлен `routerDelegate.addListener`
  в GoRouter setup. Listener:
  ```dart
  router.routerDelegate.addListener(() {
    final cfg = router.routerDelegate.currentConfiguration;
    final lastMatch = cfg.matches.isNotEmpty ? cfg.matches.last : null;
    final path = lastMatch?.matchedLocation ?? cfg.uri.path;
    final isReader = path.startsWith('/reader/');
    debugPrint('[ORIENT] route=$path isReader=$isReader');
    globalOrientationGuard.setIsReader(isReader);
  });
  ```
- `lib/main.dart` — оставлен hardcoded initial portrait-only (до
  создания router и listener). Импорт `DeviceOrientation` сохранён.
- `lib/features/quran/presentation/reader_screen.dart` — удалены:
  - import `flutter/services.dart`
  - константы `_allOrientations`, `_portraitOnly`
  - `addPostFrameCallback` в initState
  - `unawaited(SystemChrome.setPreferredOrientations(_portraitOnly))` в dispose

### Verification на устройстве

Через `adb logcat -s flutter` после tap-навигации:

```
10:50:35 [ORIENT] route=/bootstrap isReader=false  ← initial bootstrap
10:50:35 [ORIENT] route=/ isReader=false           ← home loaded
10:50:39 [ORIENT] route=/read isReader=false       ← Читать → SurahList
10:50:41 [ORIENT] route=/reader/1 isReader=true    ← Аль-Фатиха → Reader ✓
10:51:04 [ORIENT] route=/read isReader=false       ← BACK from Reader ✓
10:51:24 [ORIENT] route=/reader/2 isReader=true    ← Аль-Бакара → Reader ✓ (повторно)
10:51:44 [ORIENT] route=/read isReader=false       ← BACK from Reader again ✓
```

**Ключевая проверка**: после второго входа в Reader → Reader-2 isReader=true.
После второго back → Reader-2 → /read isReader=false. Listener работает
на каждом переходе, и `isReader` корректно отражает top-route.

### Что нужно от пользователя

**Только физическая проверка** (ColorOS блокирует programmatic
rotation через adb):
1. Запустить приложение → открыть Reader → повернуть → должно быть landscape
2. Нажать back → на SurahList/Главная → повернуть → должно быть ЗАБЛОКИРОВАНО
3. Снова открыть Reader → должно быть landscape (воспроизводит тот самый баг)

С listener-based подходом все три сценария должны работать корректно.
